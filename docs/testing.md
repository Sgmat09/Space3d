# Testing

Space3d games are tested with plain `cargo test` (or `space3d test`, which adds a report). The
harness is `space3d-test`, available through the facade's `test` feature:

```toml
[dev-dependencies]
space3d = { …, features = ["test"] }
```

```rust
use space3d::prelude::*;
use space3d::test::prelude::*;
```

## `TestApp`: deterministic and headless

`TestApp` wraps an `App` so that **every step is exactly one fixed tick** — no wall clock, no
window. It adds `InputPlugin` and `RenderPlugin`, plus a headless renderer when a GPU adapter
exists.

```rust
let mut app = TestApp::headless(320, 240);   // renderer if available
let mut app = TestApp::no_render();          // simulation only (fastest)
app.add_plugin(my_game::GamePlugin);
app.step();                                  // one tick (runs Startup first)
app.step_ticks(60);                          // one second at 60 Hz
app.run_until(|app| app.count::<Enemy>() == 0, 600)?;
```

World helpers: `find_by_name`, `translation`, `get::<C>`, `single::<C>`, `count::<C>`,
`entities_with::<C>`, `resource::<R>`, `events::<E>`.

## Input simulation

```rust
app.hold_key(KeyCode::ArrowRight, 30);            // press, 30 ticks, release
app.tap_key(KeyCode::Space);
app.click(MouseButton::Left, Vec2::new(100.0, 80.0));
app.drag(MouseButton::Left, from, to, 20);
app.touch_tap(Vec2::new(250.0, 128.0));
app.swipe(from, to, 15);
app.pinch(center, 100.0, 200.0, 20);
app.gamepad_press(0, GamepadButton::South, 5);
```

Longer sequences are `InputScript`s (tick-relative events, serializable as RON). Record one from a
real play session with `InputRecorderPlugin` and replay it in a test:

```rust
let script = InputScript::new()
    .hold_key(0, KeyCode::ArrowUp, 50)
    .hold_key(20, KeyCode::ArrowLeft, 25);
app.play(&script);
```

Because simulation runs on fixed ticks, the same script always gives the same result —
`assert_deterministic` runs two apps in lockstep and compares world fingerprints every tick.

## Golden screenshots

```rust
#[test]
fn title_screen() {
    require_gpu!();                              // skip (not fail) without a GPU
    let mut app = TestApp::headless(320, 240);
    app.add_plugin(my_game::GamePlugin);
    app.step_ticks(2);
    assert_screenshot!(&mut app, "title_screen");
    assert_screenshot!(&mut app, "title_lenient", CompareOptions::perceptual());
}
```

* Goldens live in `<crate>/tests/__screenshots__/<name>.png`. **The first run writes them** —
  review and commit them.
* On mismatch the test fails and writes `<name>.actual.png` and `<name>.diff.png` next to the
  golden (ignored by the generated `.gitignore`).
* Re-bless intended changes: `space3d test --update-snapshots` (sets
  `SPACE3D_UPDATE_SNAPSHOTS=1`).
* GPUs differ slightly: `CompareOptions` has per-channel tolerance, allowed differing-pixel
  fraction and SSIM; `SPACE3D_SNAPSHOT_VARIANT=backend|os|os-backend` stores per-platform goldens
  when a backend renders visibly differently.

### Environment switches

| variable | effect |
|---|---|
| `SPACE3D_UPDATE_SNAPSHOTS=1` | re-bless goldens instead of comparing |
| `SPACE3D_CI=1` / `CI=true` | a missing golden is a failure (not silently written) |
| `SPACE3D_SNAPSHOT_VARIANT=…` | write platform-specific goldens |
| `SPACE3D_REQUIRE_GPU=1` | fail instead of skip without a GPU |
| `SPACE3D_NO_GPU=1` | pretend there is no GPU (test the skip paths) |
| `SPACE3D_TEST_REPORT=dir` | write `results.jsonl`, `report.json`, `index.html` |
| `SPACE3D_PERF_BUDGET_SCALE=2` | loosen performance budgets on slow machines |

## `space3d test`

```sh
space3d test                          # cargo test + report summary
space3d test -- player                # test-name filter
space3d test --update-snapshots
space3d test --report out/report      # default: target/space3d-report
space3d test --workspace
```

After the run it prints counts per status (passed / failed / created / skipped), every failed
screenshot with its diff image, and the path of the HTML report (expected / actual / diff side
by side).

Each run starts a fresh report: the previous report's own files (`results.jsonl`,
`report.json`, `index.html`, `images/`) are removed, nothing else. A `--report` directory that
is not empty and holds no previous report (e.g. `--report docs`) is refused rather than cleared.

## Performance assertions

```rust
assert_frame_budget(&mut app, 120, Duration::from_millis(4));   // average CPU frame time
RenderBudget::new()
    .max_draw_calls(10)
    .max_bytes_uploaded(64)          // a static scene should upload (almost) nothing
    .assert_frame(&mut app);         // renders one frame, checks its RenderStats
```

`space3d_test::install_counting_allocator!();` (once per test binary) +
`assert_max_allocations(n, || app.step())` catch per-frame allocations.

## CI

The workflow generated by `space3d new` / `space3d ci init` runs `cargo fmt --check`,
`cargo clippy -D warnings` and `cargo test` on Ubuntu with Mesa's software Vulkan driver
(lavapipe), so screenshot tests really render in CI; on failure it uploads `*.actual.png` and
`*.diff.png` as an artifact.
